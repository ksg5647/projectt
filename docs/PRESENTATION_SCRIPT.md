## 2. 해커톤 주제와의 연결

### 발표 문장

> 이번 해커톤의 주제는  
> **‘AI와 미래의 공존: 무한한 상상, 무해한 AI’**입니다.
>
> 저희는 미래에 AI가 **뉴스의 단서를 분류하고 판단 이유를 설명하는 역할**을 통해 사람을 도울 수 있다고 상상했습니다.
> 동시에 **잘못된 판정을 실제 사실로 믿거나 공유하는 위험**을 예방하기 위해 **규칙과 판단 이유를 공개하고, 추가 확인이 필요하다는 안내를 제공하는 장치**를 적용했습니다.

### 발표할 내용

- 사람과 AI가 공존하는 방법: AI는 단서를 정리하고 사람은 근거를 확인해 최종 판단을 내립니다.
- 우리 팀의 새로운 상상: 게임 결과 뒤에 판별법 가이드와 체크리스트를 연결했습니다.
- 예방하려는 위험: 가짜뉴스를 그대로 믿거나 확인 없이 공유하는 위험입니다.
- 적용한 안전 장치: 개인정보와 외부 API를 사용하지 않고, 규칙 기반 참고 결과라는 한계와 추가 확인 방법을 안내합니다.

## 3. 핵심 기능 소개

### 발표 문장

> 사용자가 **뉴스 카드를 읽고 진짜 뉴스 또는 가짜 뉴스를 선택**하면 앱은
> **출처, 날짜, 과장된 표현, 근거 유무를 확인하는 규칙**을 이용해 **정답 여부, 점수, 판단 이유**를 보여 줍니다.
>
> 저희가 반드시 구현하려고 했던 핵심 기능은  
> **뉴스 단서 확인, 진짜·가짜 선택, 결과와 해설 확인**입니다. 지금부터 직접 시연하겠습니다.

## 4. 앱 시연

### 시연 순서

1. 초기 화면을 보여 줍니다.
2. 사용자의 입력 또는 선택을 보여 줍니다.
3. 핵심 버튼을 누릅니다.
4. 결과와 판단 이유를 설명합니다.
5. 사용자가 최종적으로 선택할 수 있는 행동을 보여 줍니다.

### 시연에 사용할 입력

```text
예시 문제: 출처가 표시되지 않고 “지금 당장 공유하세요!”처럼 감정을 자극하는 표현이 많은 뉴스 카드
선택: “가짜다” 버튼
```

### 기대 결과

```text
결과: 정답입니다. 점수가 올라갑니다.
판단 이유: 출처와 근거가 부족하고 감정을 자극하는 표현이 많아 추가 확인이 필요합니다.
다음 행동: 다음 문제로 이동하거나 게임을 처음부터 다시 시작할 수 있습니다.
```

### 발표 문장

> 먼저 사용자가 **뉴스 카드의 출처, 날짜, 표현과 근거를 확인한 뒤 진짜 또는 가짜를 선택**합니다.
> **‘진짜다’ 또는 ‘가짜다’** 버튼을 누르면 **정답 여부, 점수, 판단 이유와 판별 단서**가 나타납니다.
>
> 이 결과는 **출처가 없고 자극적인 표현이 많으면 가짜뉴스 가능성을 높게 보고, 출처·날짜·근거가 있으면 진짜뉴스 가능성을 높게 보는 규칙**에 따라 만들어졌습니다.
> 앱은 결과만 보여 주지 않고 **출처와 근거를 확인해야 하는 이유**도 함께 설명합니다.
>
> 사용자는 이 결과를 참고한 뒤 **다음 문제로 갈지, 처음부터 다시 할지, 판별법 가이드를 확인할지**를 직접 선택할 수 있습니다.

## 5. AI 또는 AI적 판단 방식

### 판단 흐름

```text
사용자의 입력
→ 입력값 검사
→ 규칙 또는 점수 계산
→ 결과와 판단 이유 표시
→ 사용자가 최종 결정
```

### 우리 프로젝트의 판단 흐름

```text
입력
→ 뉴스 카드와 판별 단서 확인
→ 진짜 또는 가짜 선택
→ 규칙에 따른 정답·점수·판단 이유 표시
→ 사용자가 다음 행동 결정
```

### 발표 문장

> 저희 프로젝트는 실제 생성형 AI API 대신  
> **미리 작성한 데이터 목록, 조건문, 점수 계산**을 사용했습니다.
>
> 사용자가 **진짜 또는 가짜를 선택**하면 **뉴스 카드에 저장된 정답과 출처·날짜·근거 단서 규칙**에 따라 결과를 계산합니다.
> 이를 통해 AI가 판단하는 과정을 안전하게 시뮬레이션했습니다.

## 6. 왜 ‘무해한 AI’인가?

### 확인 항목

- 개인정보를 수집하지 않는가?
- 특정 사람이나 집단을 차별하지 않는가?
- 혐오·폭력·위험 행동을 추천하지 않는가?
- 판단의 한계를 사용자에게 알리는가?
- 사용자가 최종적으로 결정할 수 있는가?

### 발표 문장

> 이 기능이 잘못 판단하면 **사용자가 잘못된 확인 기준을 배우거나 결과를 실제 사실로 과신하는 문제**가 생길 수 있습니다.
> 이를 예방하기 위해 **판단 이유와 규칙을 함께 보여 주고, 실제 원문과 여러 출처를 추가로 확인하라는 안내**를 적용했습니다.
>
> 또한 AI적 규칙의 결과를 정답으로 강요하지 않고
> 사용자가 **뉴스를 추가로 확인하고 다음 문제, 다시하기, 판별법 가이드 중 하나를 선택**할 수 있게 만들었습니다.
>
> 이러한 점에서 저희 프로젝트는 사람에게 도움을 주면서도  
> 위험을 줄이는 ‘무해한 AI’를 표현합니다.

## 7. AI 코딩 도구 활용

### 가장 도움이 된 요청

```text
가짜뉴스 판별게임의 핵심 기능을 3시간 안에 구현할 수 있도록, 뉴스 카드와 진짜·가짜 선택 버튼을 만들고 선택 결과에 정답 여부, 점수, 판단 이유, 다음 문제 버튼을 표시해 주세요. 개인정보와 외부 API는 사용하지 말고, 정상 입력·오답 입력·마지막 문제를 테스트할 수 있게 해 주세요.
```

### 요청에 포함한 내용

- 구현할 기능: 뉴스 카드, 진짜·가짜 선택, 정답 판정, 점수, 해설, 다음 문제와 다시하기
- 수정할 파일: `index.html`, `style.css`, `script.js`
- 변경하면 안 되는 부분: 개인정보 수집, 외부 API 키 사용, 실제 인물이나 언론사를 공격하는 사례
- 완료 기준: 선택 후 정답 여부·점수·판단 이유가 표시되고 다음 문제로 이동할 수 있음
- 테스트 기준: 정상 선택, 오답 선택, 선택하지 않은 상태, 마지막 문제, 초기화 동작

### AI 결과에서 발견한 문제

> AI가 만든 결과에서 일부 화면 상태가 연결되지 않거나, 다음 문제와 다시하기 동작에서 점수와 진행 번호가 초기화되는지 추가 확인이 필요했습니다.

### 직접 검증하고 수정한 방법

> 김태인과 강승구가 요구사항과 코드를 함께 확인하고, 선택 후 해설 표시, 다음 문제 이동, 다시하기 초기화, 마지막 문제 종료를 순서대로 테스트했습니다.

### 발표 문장

> AI 코딩 도구에는 한 번에 기능 하나를 요청했습니다.  
> 특히 수정할 파일과 완료 기준을 구체적으로 알려 주었습니다.
>
> AI가 만든 결과에서 **게임 상태와 화면 전환을 추가로 확인해야 하는 문제**를 발견했고,
> **두 팀원이 정상 선택·오답 선택·마지막 문제·다시하기를 직접 실행해 검증하는 방법**으로 해결했습니다.

## 8. 테스트와 오류 수정

### 대표 테스트

| 입력 또는 조작                       | 기대 결과                       | 실제 결과                       | 통과 여부 |
| ------------------------------------ | ------------------------------- | ------------------------------- | :-------: |
| 뉴스 카드를 읽고 진짜 또는 가짜 선택 | 정답 여부, 점수, 판단 이유 표시 | 정답 여부, 점수, 판단 이유 표시 |   통과    |
| 선택하지 않고 결과를 확인하려고 시도 | 선택 안내, 점수 변화 없음       | 선택 안내, 점수 변화 없음       |   통과    |
| 마지막 문제까지 답변                 | 최종 점수와 게임 종료 안내      | 최종 점수와 게임 종료 안내      |   통과    |

### 발견한 오류

- 재현 순서: 문제에 답한 뒤 다음 문제와 다시하기를 반복해서 선택합니다.
- 기대 결과: 다음 문제에서는 진행 번호가 증가하고, 다시하기에서는 점수와 진행 번호가 초기화됩니다.
- 실제 결과: 화면 전환 뒤 상태가 올바르게 바뀌는지 확인이 필요했습니다.
- 오류 원인: 게임 진행 상태와 화면 상태를 따로 확인하지 않았기 때문입니다.
- 수정 방법: 정답 선택 후 해설 화면을 표시하고, 다음 문제와 다시하기 동작을 분리해 점검했습니다.
- 다시 테스트한 결과: 정상 선택, 오답 선택, 마지막 문제, 다시하기 순서에서 기획한 결과를 확인했습니다.

### 발표 문장

> 테스트 과정에서 **다음 문제와 다시하기 뒤 진행 상태를 확인해야 하는 오류**를 발견했습니다.
> 기대한 결과는 **다음 문제에서는 번호가 증가하고 다시하기에서는 점수가 0점으로 돌아가는 것**이었지만 실제로는 **상태 연결을 추가로 점검해야 하는 상황**이었습니다.
>
> 원인은 **게임 상태와 화면 전환을 함께 점검하지 않은 것**이었고, **각 동작을 분리해 테스트하고 초기화 흐름을 확인하는 방법**으로 해결했습니다.
> 수정한 뒤 동일한 조건에서 다시 테스트해 정상 작동을 확인했습니다.

## 9. 역할과 마무리

### 역할

- 팀원 1: 김태인 - 핵심 게임 흐름, 정답 판정, 점수 계산, 판단 규칙 발표
- 팀원 2: 강승구 - 화면 구성, 결과 화면, 판별법 가이드, 안전 설계 발표
- 드라이버와 내비게이터 교대 방법: 0~35분 김태인·강승구로 시작하고, 35분 이후 시간대별로 드라이버와 내비게이터를 교대했습니다.

### 발표 문장

> **김태인**은 주로 **핵심 게임 흐름과 정답 판정**을 담당했고,
> **강승구**는 주로 **화면 구성과 판별법 가이드**를 담당했습니다.
>
> 개발 중에는 드라이버와 내비게이터 역할을 교대하며  
> 코드와 AI의 답변을 함께 검토했습니다.
>
> 이번 프로젝트를 통해 **AI나 규칙 기반 결과도 사람이 근거와 한계를 함께 확인해야 한다는 점**을 배웠습니다.
> 시간이 더 있다면 **더 다양한 뉴스·사진·영상 문제와 실제 출처를 확인하는 학습 기능**을 추가하고 싶습니다.
> 이상으로 발표를 마치겠습니다.

## 11. 시연 중 오류가 발생했을 때

### 대체 발표 문장

> 현재 시연 과정에서 예상하지 못한 오류가 발생했습니다.  
> 원래 기대한 결과는 **사용자의 선택 뒤 정답 여부, 점수, 판단 이유가 표시되는 것**입니다.
>
> 개발 중에는 **정상 선택, 오답 선택, 마지막 문제, 다시하기 테스트**까지 작동했습니다.
> 현재 추정하는 원인은 **게임 상태와 화면 전환 과정의 연결 문제**이며 발표 후 다시 확인하겠습니다.

### 미리 준비할 자료

- 정상 작동 화면 캡처
- 짧은 시연 영상
- GitHub 저장소 주소
- 마지막 정상 커밋
